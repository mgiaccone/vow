# vow

`vow` generates value objects and enums for Go: types whose underlying value
can only be constructed through a fallible, sanitizing constructor. The
sentence that governs every decision here: **values are parsed once, at
construction, and are unforgeable thereafter.**

## Commands

```
go test ./...                          # full suite
go test ./cmd/vow -update              # refresh golden files
go generate ./...                      # regenerate example/
go vet ./... && gofmt -l .
```

## Layout

- `vow.go`, `sanitizers.go`, `rules.go`, `collect.go` — the runtime, at the
  module root so consumers write `vow.Spec[string]{...}` after one import.
- `cmd/vow/` — the generator. Never a runtime dependency; nothing in it may be
  imported by root-package code.
- `internal/testdata/` — golden fixtures. Directories named `testdata` are
  invisible to `go build`/`go vet`/`go test ./...`, which is why fixtures can
  reference not-yet-generated code without breaking the build.
- `example/` — dogfoods the generator via the `tool` directive in `go.mod` and
  holds the runnable godoc `Example` functions.
- `README.md` — the project's only documentation; there is no `docs/`.

## Hard invariants

Each exists for a reason a quick fix will route around if you don't know it.

- **No underscores in any user-facing name** — flags, tag keys/values,
  directives, sanitizer names. Hyphens where unavoidable, single words where
  not. `sanitize=trim|collapse` has to stay unambiguous with no separator.
- **Zero third-party dependencies, anywhere, including tests.** This is the
  entire pitch to adopters weighing a codegen tool; one `require` line undoes
  it.
- **No `go/types`, no `x/tools`, anywhere in the generator.** `go/types` is
  used exactly once, as `types.ExprString` — a syntactic printer, not a
  checker — to render a field's base type. Don't "improve" this into real
  type-checking; see the next invariant for why.
- **The generator must work on a package that does not compile.** First
  adoption always starts with code that calls `NewEmail` before `NewEmail`
  exists. Discovery uses `go/parser` and purely syntactic checks for exactly
  this reason.
- **No validation rules in struct tags.** Tags are backtick literals: no
  embedded quotes, and splitting on `,` corrupts any regex containing one.
  Rules stay as ordinary, type-checked Go.
- **No `UnmarshalJSON` on generated types.** A decode error carries no field
  identity, so it can't join a `Collector` result. Decode into a string DTO
  and call `New<T>` where the field is known.
- **No validation in `Scan`.** Retiring an enum member or tightening a rule
  must never make historical rows unloadable.
- **One output file per package, not configurable.** Spec vars and enum
  consts are resolved across the whole package, so the package is already the
  unit of input; per-file output would need the generator to delete files it
  believes it owns, which it must never do.
- **`vow` never deletes a file.** It writes exactly `-out` and touches nothing
  else. If a package's last tagged type is removed, the generator errors and
  names the stale file rather than silently clearing it.
- **Output must be byte-identical across runs.** Sorted declarations, sorted
  map iteration, no `time.Now()`/`math/rand` anywhere in generation. This is
  what makes `go generate ./... && git diff --exit-code` a valid CI check.

## Conventions

- Every generation error carries a `token.Position`, names the type, and
  states the fix — see `errAt` in `cmd/vow/errors.go`.
- Rule messages are transport-neutral sentence fragments ("must be at most 254
  characters"), never a full sentence or an HTTP-flavored one. Built-in rules
  return an unexported `ruleError` rather than `fmt.Errorf("...: %w", sentinel)`
  so the sentinel's own text doesn't leak into the fragment; `errors.Is` still
  reaches it.
- Generated files start with `// Code generated by vow. DO NOT EDIT.`.
- Iterate in sorted order everywhere output touches disk.

## When changing the generator

1. Run `go test ./cmd/vow -update`.
2. Read the golden diff by eye — don't accept it unread.
3. Run `go generate ./...` and confirm `example/` still builds and vets.
4. Run generation a second time and confirm it produces no diff.

## What to ask about rather than decide

Public API changes (runtime or generated method set), new struct-tag or
directive options, and anything that would add a dependency — including a
GitHub Action beyond `actions/checkout`/`actions/setup-go`.
